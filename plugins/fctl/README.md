# fctl Flows plugin — preparation tranche

This directory is the Flows-owned preparation for the fctl Flows plugin
(fctl-v2 programme Task 10B). It currently contains **no plugin**: no runtime,
no component entry point, no HTTP client, no generated bindings, no ABI. It
contains the one thing that can be delivered and defended before the fctl-v2
plugin runtime is frozen — a reproducible, versioned inventory of the
orchestration operation surface and its mapping onto the legacy fctl command
baseline.

## Why the inventory comes first

The fctl-v2 programme gates every product plugin implementation behind its MVP4
contract freeze (portable component lifecycle, host-owned access and
capabilities, exact per-operation authorisation scopes). Writing a catalogue or
an adapter against an unfrozen ABI would produce work that has to be thrown
away.

For Flows there is a second, product-local reason: Task 10B requires the plugin
to route every operation through this repository's generated `pkg/client`, and
that client does not build. It declares `module openapi` while its own sources
import two other paths, and its `go.sum` carries no module-content hash. That
is recorded as blocker B1 with a reproducing command, and it is deliberately
**not** repaired here — the client is regenerated by `just generate-client`, so
its module path is a generation-configuration decision, not a hand edit.

## Contents

| Path | Role |

| `audit/testdata/report.json` | Golden report; the determinism gate. |
| `cmd/specaudit` | Regenerates the two committed artefacts. |

## Commands

Run from the repository root inside `nix develop`:

```sh
just fctl-audit         # regenerate the committed inventory artefacts
just fctl-audit-check   # fail if they no longer match openapi.yaml
```

Or from this directory:

```sh
go test ./...
```

`just tests`, `just lint`, `just tidy` and `just pre-commit` at the repository
root include this module.

## Module path

This module declares `github.com/formancehq/orchestration/plugins/fctl` — a
subdirectory of the repository root module path in the root `go.mod`. That is
this repository's authoritative module namespace even though its VCS name is
`formancehq/flows`. The generated client assumes the other namespace; §7 of the
inventory records that conflict rather than resolving it here.

## What must not be inferred from this directory

- No operation is accepted into a plugin catalogue. The inventory records
  proven facts and separately records blockers. All 35 operations are currently
  blocked.
- No authorisation scope is invented. The declared scopes are read from the
  document, and the fact that the service checks them by HTTP method rather
  than by operation — and not at all by default — is recorded, not smoothed
  over.
- No transport, component build, OCI installation or dual-host behaviour is
  claimed, prepared or gated here.
